# Population discrimination observer

This pipeline consumes the compact population evidence table generated by
`notebooks/04_FeatureEngineering.ipynb`. It does not load the
multi-gigabyte population-response CSVs and does not run NEURON.

The default manuscript-oriented specification uses:

- per-frequency operating-state weights shared by std0 and std1;
- standard-block readouts shared across frequencies, per-frequency readouts
  shared by std0/std1, and full per-frequency x standard-block readouts;
- matched per-frequency MC-selected best-single and convex-mixture representations;
- fixed global-single and fixed per-frequency-single controls selected once
  from all simulation replicates and held constant across MC splits;
- rate-only, timing-only, ungated-hybrid, and delta-CV-gated-hybrid models;
- the manuscript mixture prior (`KL=0.01`, effective-count floor `K=3`
  with `lambda=0.01`, and maximum weight `0.65` with `lambda=0.01`);
- latent-trial mixture semantics; and
- 200 Monte Carlo replicate splits in 20 shards.

The default partial root is versioned as
`results/partials/discrimination_v4_manuscript_regularized`, so an
updated run cannot be contaminated by shards from the earlier 40-shard design.

Before fitting, exact duplicate responses are collapsed separately at each
frequency using their complete CV x replicate tensors over the five raw
population features that generate the observer evidence.
Amplitude proximity alone never triggers a merge. Nominally tied definitions
receive combined labels; otherwise the label whose nominal target is closest
to the realized CV0 index-spike count is retained. Original rows remain in the
evidence and raw parameter-weight files for provenance. Frequency-specific and
frequency-by-standard mixtures fix inactive duplicate rows to zero. A mixture
shared across frequencies retains nominal-state parameters because a pair can
be equivalent at one frequency but distinct at another; its reported and
regularized masses are collapsed into response-equivalent classes separately
at every frequency where that vector is applied.

The per-panel model mirrors the finalized single-axon release: the
operating-state mixture is the representation being shared, while observer
parameters are fitted for each frequency x standard panel. The nested
per-frequency model preserves frequency-dependent cue reliance but requires
std0 and std1 to share a readout. The crossed per-block sensitivity model lets
std0 and std1 differ but shares each standard's readout across frequencies.

The MC-selected best-single comparator exhaustively evaluates each frequency's
states when the readout also factors by frequency. For the per-standard
readout, where frequencies are coupled, every shared named state is seeded and
the best solution is refined by reoptimizing the readout for every coordinate
candidate. The two `fixed_single` controls optimize the state choice once using
all 100 simulation replicates, then refit only the observer readout within
every MC training split.

Mixtures use an identifiable K-1-logit simplex parameterization. All continuous
fits use bounded L-BFGS-B with a large numerical-gradient evaluation budget and
an extended retry after a failed stopping flag. Multistart selection prefers a
formally converged solution before comparing objective values. Final validation
is strict: any unsuccessful optimizer fit makes the run fail validation.

As in the submitted single-axon model, mixture diversity is encouraged rather
than imposed as a hard constraint. The effective-count and maximum-weight
penalties therefore express the experimental prior that a stable one- or
two-state operating point is implausible while still allowing the likelihood to
overcome that prior when the data strongly require it. After exact response
equivalence is removed, the effective-count target is capped at the number of
distinct classes available at that frequency. `validation.json` reports the
achieved effective counts and maximum weights so this assumption is auditable.

Run the focused crossed-hypothesis pilot (32 one-CPU tasks; eight MC splits for
each hypothesis):

```bash
bash slurm/discrimination/run_population_discrimination_scope_pilot.sh
```

It compares only the ungated hybrid latent-trial mixtures needed for the next
decision:

- per-frequency mixtures + per-frequency readout (frequency-only baseline);
- per-standard mixtures + per-frequency readout (standard-specific states);
- per-frequency mixtures + per-standard readout (standard-specific cue use);
- per-panel mixtures + per-panel readout (interaction upper bound).

`OBSERVER_SPECS_CSV` uses
`weight_scope:readout_scope:state_mode` entries and can be overridden without
creating a Cartesian sweep.

After auditing that pilot, submit the same four hypotheses over 200 MC splits:

```bash
bash slurm/discrimination/run_population_discrimination_scope_full.sh
```

The full wrapper submits 800 one-CPU array tasks (one MC split per task) with a
`%800` throttle. It writes to the separately versioned
`discrimination_v5_scope_hypothesis_full` partial and merged result roots.

From the Longleaf project root, validate without submitting jobs:

```bash
DRY_RUN=1 bash slurm/discrimination/run_population_discrimination_pipeline.sh
```

Run a two-split convergence pilot covering all three readout scopes, all four
state specifications, and all four model specifications (48 one-CPU tasks;
96 fitted MC configurations):

```bash
bash slurm/discrimination/run_population_discrimination_equivalence_pilot.sh
```

Override `PILOT_NAME` to retain multiple pilot versions. The wrapper exposes
the same environment variables as the main runner when a narrower diagnostic
is needed.

Keep pilot and final partial roots separate. The merger intentionally consumes
every shard below its partial root, so mixing pilot and final shard layouts
would duplicate Monte Carlo indices.

Submit the full default analysis:

```bash
bash slurm/discrimination/run_population_discrimination_pipeline.sh
```

The full comparison contains 960 one-CPU array tasks and defaults to a `%960`
array throttle. Each task handles ten Monte Carlo splits. This stays below a
roughly 1,000-element Slurm array limit while using nearly all 1,000 available
CPUs concurrently.

To compare latent-trial and legacy evidence-average mixture semantics in a
small mixture-only pilot, use a separate output root:

```bash
MC_TOTAL=4 MC_SHARDS=4 STATE_SPECS_CSV=per_frequency:mixture \
  MIXTURE_SEMANTICS_CSV=latent_trial,evidence_average \
  PARTIAL_ROOT="$PWD/results/partials/discrimination_semantics_pilot" \
  OUT_ROOT="$PWD/results/discrimination/pilot/semantics" \
  bash slurm/discrimination/run_population_discrimination_pipeline.sh
```

The dependent merge job writes MC summaries and stable notebook-facing files
under `results/discrimination/control/`, including:

- `population_observer_rmse.csv`
- `population_discrimination_curves.csv`
- `population_observer_weights.csv`
- `population_observer_effective_weights.csv`
- `population_observer_readout.csv`
- `population_effective_rate_share.csv`
